The project uses 3 AI models. Here is what you need to do for each:

| Model | File | Action Required |

| **YOLOv8n Face Detector** | `yolov8n-face.pt` | ✅ **Auto-downloaded** on first run (via Ultralytics) |

**For the Mask Detector:**

1. Obtain a custom-trained YOLOv8 mask detection model (`mask_detector.pt`)
2. Place it in:
   ```
   face-mask-attendance/
   └── backend/
       └── ml_models/
           └── mask_detector.pt   ← place here
   ```

> **If you don't have a mask detector model:**  
> The app will still work — it will log a warning and default to recording `mask_detected = False` for all attendance entries. Face recognition will still function normally.

### 🔴 Common Issues & Fixes

| Problem | Cause | Fix |
|---------|-------|-----|
| `could not connect to server` | PostgreSQL not running or wrong password | Start PostgreSQL service; check DATABASE_URL password |
| `ModuleNotFoundError: insightface` | insightface not installed | `pip install insightface` (needs C++ build tools on Windows) |
| `No such file: mask_detector.pt` | Model file missing | Place the file in `backend/ml_models/` or ignore (app degrades gracefully) |
| `Camera not accessible` | Webcam in use by another app | Close other camera apps (Zoom, Teams, etc.) |
| `PermissionError on venv\Scripts\Activate.ps1` | PowerShell execution policy | Run: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `Face not recognized` | Low recognition confidence | Lower `RECOGNITION_THRESHOLD` to `0.45` in `.env`; re-generate embeddings |
| `Attendance not marking` | Student not registered with embeddings | Complete the face registration flow for the student |
| `port 5000 already in use` | Another app using port 5000 | Kill the process or change port in `app.py` to e.g. `5001` |
